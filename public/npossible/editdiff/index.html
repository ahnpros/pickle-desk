판 고친 글, 무엇이 바뀌었는지 세 가지로 나눕니다

표현만 고친 수정, 뜻이 바뀐 수정, 개인정보를 지운 수정. 셋을 같은 방식으로 보여 주면 뒤의 둘이 앞의 하나에 묻힙니다.

아침에 지하철에서 가방을 주웠어요

겨울나무3시간 전 수정됨 · 3번 고침

댓글

댓글은 문장 하나에 붙습니다. 그 문장이 뜻까지 바뀌면 댓글 위에 표시가 생깁니다.

바뀐 것

독자에게는 뜻이 바뀐 수정과 개인정보 삭제만 알립니다. 맞춤법만 고친 수정은 ‘수정됨’ 표시 안에 접어 둡니다.

이 화면이 쓰는 규칙

미션이 짚은 네 가지

미션 문장을 그대로 화면 조건으로 옮겼습니다. 새 기능을 더하지 않고, 이미 있는 글 화면에 무엇을 붙일지 정했습니다.

미션이 말한 것화면에서의 답
고쳐져도 무엇이 바뀌었는지 알 수 없다글 제목 아래에 수정됨 · 3번 고침을 두고, 누르면 문장 단위로 바뀐 곳을 보여 줍니다. 바뀐 문장은 원문 위치에 그대로 표시합니다.
댓글을 달았는데 원글이 바뀌면 내 댓글 뜻이 어색해진다댓글을 문장 하나에 붙여 저장합니다. 그 문장이 뜻까지 바뀌면 댓글 위에 “댓글을 단 문장이 바뀌었어요”를 붙이고, 바뀐 전후를 그 자리에서 보여 줍니다.
맞춤법 수정과 뜻이 바뀐 수정은 다르게 다뤄야 한다두 가지를 다른 판정으로 나눕니다. 숫자·부정어·노선이나 시점 표현이 바뀌면 뜻이 바뀐 수정으로 올리고, 조사·어미·띄어쓰기만 바뀌면 표현 수정으로 접습니다. 판정 근거를 카드에 그대로 적습니다.
개인정보를 지우는 수정은 내역까지 공개하면 안 된다전화번호·메일·계좌 같은 값이 사라진 수정은 내용을 저장하지도 보여 주지도 않습니다. “전화번호가 지워졌어요”만 남기고, 원문은 비교 대상에서 뺍니다.

왜 ‘수정 내역 전체 공개’가 답이 아닌가

내역을 다 보여 주면 맞춤법 한 글자까지 읽어야 하고, 그 사이에 뜻이 바뀐 문장이 묻힙니다. 그리고 개인정보를 지운 사람에게 “무엇을 지웠는지”를 다시 보여 주는 셈이 됩니다. 그래서 공개 기본값은 뜻이 바뀐 것과 지운 사실이고, 표현 수정은 접어 둡니다. 작성자만 자기 글의 전체 내역을 봅니다.

한계. 뜻이 바뀌었는지는 기계가 완벽히 알 수 없습니다. 이 화면은 숫자·부정어·고유명사의 변화만 보고 판정하고, 애매하면 “확인 필요”로 남깁니다. 판정을 확신으로 쓰지 않습니다.

판정 규칙

[한 번 고칠 때]
  1. 이전 문장과 새 문장을 단어 단위로 비교한다(공백·조사 포함).
  2. 사라진 토막에 전화번호·메일·계좌·주민번호 모양이 있으면
     → 개인정보 삭제 (내용 저장 안 함, 유형만 남김)
  3. 숫자, 부정어(안·못·없·아니), 노선 이름, 시점(오늘·내일)이 바뀌었으면
     → 뜻이 바뀐 수정
  4. 그 밖에 글자만 바뀌었으면 → 표현 수정
  5. 3번과 4번 사이에서 판단이 서지 않으면 → 확인 필요 (작성자에게 한 번 묻는다)

상태 전이

[글] 게시 → (고침) → 수정됨 표시 + 변경 목록
     ├─ 표현 수정만       → 배지: "수정됨"        (목록은 접힘)
     ├─ 뜻이 바뀐 수정 있음 → 배지: "뜻이 바뀐 수정"  (목록 펼침)
     └─ 개인정보 삭제 있음  → 배지: "개인정보 지움"   (내용 없음)
[댓글] 문장에 붙음
     ├─ 붙은 문장 그대로   → 그냥 댓글
     ├─ 붙은 문장 뜻 바뀜  → "댓글을 단 문장이 바뀌었어요" + 전후 보기
     └─ 붙은 문장 지워짐   → "댓글을 단 문장이 지워졌어요" + 원문 인용은 접힘

엣지케이스

상황처리
개인정보를 지운 뒤 같은 글을 또 고침지운 값은 저장하지 않으므로 다음 비교에도 나오지 않습니다. “지웠다”는 사실과 유형만 남습니다.
댓글 단 문장이 통째로 사라짐댓글은 남기고, 인용하던 원문은 접습니다. 지운 이유가 개인정보라면 인용도 함께 감춥니다.
맞춤법만 고쳤는데 숫자가 하나 바뀜숫자 변경은 뜻이 바뀐 수정으로 올립니다. 판정 근거에 “숫자 1개 바뀜”을 적어 작성자가 바로 알게 합니다.
아주 긴 글을 여러 번 고침문장 단위로만 비교하고, 바뀐 문장이 없으면 저장하지 않습니다. 전체 글을 매번 복사하지 않습니다.
작성자가 수정 이력을 지우려 함뜻이 바뀐 수정과 개인정보 삭제 기록은 지울 수 없습니다. 표현 수정 기록만 접을 수 있습니다.
화면 낭독기변경 카드마다 “삭제: … / 추가: …”를 문장으로 읽고, 색만으로 구분하지 않습니다.

저장 비용은 숫자로 확인합니다

아래 수치는 이 페이지가 지금 들고 있는 예시 글 4개 버전에서 실제로 센 글자 수입니다. 추정이 아닙니다.

무엇을 저장하는가

  • 표현 수정: 바뀐 문장의 전후만 저장합니다. 전체 글 복사본을 만들지 않습니다.
  • 뜻이 바뀐 수정: 전후 문장과 판정 근거를 남깁니다. 댓글이 붙은 문장이면 댓글 위치도 함께.
  • 개인정보 삭제: 지워진 값을 저장하지 않습니다. 유형과 시각만 남기므로 저장량이 가장 적고, 남길 것도 가장 적습니다.

아직 모르는 것

  • 실제 판 이용자가 수정 표시를 몇 번 여는지는 모릅니다. 이 페이지는 여는 횟수를 세지 않습니다.
  • 뜻이 바뀐 수정의 비율도 모릅니다. 예시 글은 제가 쓴 것이고, 실제 글 분포가 아닙니다.
  • 서버 저장 비용은 이 화면에서 계산할 수 없습니다. 여기서 잰 것은 저장할 문자열의 크기까지입니다.

이 페이지에서 직접 확인할 수 있는 것

확인하려는 것하는 방법
맞춤법 수정이 뜻이 바뀐 수정으로 잘못 올라가지 않는가변경 목록에서 두 번째 카드를 봅니다. “했어요 → 하라고 했어요”만 바뀌었는데 표현 수정으로 접혀 있는지 확인합니다.
숫자나 지명이 바뀌면 뜻이 바뀐 수정으로 올라가는가세 번째 카드에서 “3호선 → 2호선”, “오늘 → 내일”을 확인합니다. 근거에 숫자와 시점이 바뀌었다고 적혀 있습니다.
개인정보를 지운 수정이 내용을 흘리지 않는가개인정보 카드에 전화번호가 보이지 않는지, “지워진 값은 저장하지 않습니다”만 있는지 확인합니다. 페이지 소스에도 값이 없습니다.
댓글이 붙은 문장이 바뀌면 댓글에 표시가 생기는가댓글 영역에서 표시가 붙은 댓글을 확인하고, 「바뀐 곳 보기」를 눌러 그 문장의 전후를 봅니다.
독자와 작성자가 보는 양이 다른가오른쪽 위 독자로 보기 / 작성자로 보기를 바꿔 봅니다. 표현 수정 카드가 나타났다 사라집니다.

※ 사람을 모아 검증한 결과가 아닙니다. 이 페이지는 화면 동작과 판정 결과만 보여 줍니다.

처음 낸 화면에서 받은 반응과 고친 것

받은 반응바꾼 것
사용자 패널 둘 다 “숫자나 날짜가 그대로여도 말뜻이 달라지는 수정은 놓칠 수 있다”반대말 목록을 넣었습니다. 허용과 금지, 가능과 불가, 찬성과 반대처럼 뜻이 뒤집히는 짝을 감지하면 뜻이 바뀐 수정으로 올립니다. 예시 글에 다섯 번째 수정을 더해 허용이 금지로 바뀌는 경우를 넣었습니다. [체험 탭]
리뷰어 “키워드 규칙만으로는 허용을 금지로 바꾼 수정도 접힐 수 있고, 전화번호·메일·계좌 밖의 개인정보가 노출되지 않는다는 근거도 부족하다”개인정보 모양을 넓혔습니다. 주민등록번호, 카드번호, 여권번호, 주소를 더했습니다. 그래도 규칙으로 다 잡을 수 없으므로, 긴 문장이 크게 줄었는데 모양이 맞지 않으면 확인 필요로 멈추고 내용을 접은 채 작성자에게 한 번 묻습니다. 아래 판정 시험대에서 직접 넣어 볼 수 있습니다.
운영감사 “개인정보 탐지 누락을 막고, 문장이 이동하거나 쪼개져도 댓글 연결을 유지하는 비용”누락은 확인 필요 상태로 넘겨 사람이 한 번 보게 했고, 댓글 연결은 문장 번호가 아니라 문장 식별자로 잡고 문장이 쪼개지면 앞 문장에 붙이도록 적었습니다. 비용은 셋째 탭에 남겼습니다.

판정 시험대

두 문장을 넣으면 지금 쓰는 규칙으로 판정합니다. 이 페이지 안에서 실제로 계산합니다.

바꾸지 않은 것

  • 모든 개인정보를 잡는다고 쓰지 않았습니다. 규칙이 놓치면 확인 필요로 멈추는 것이 이번 버전의 답입니다.
  • 뜻 판정을 자동 확정으로 쓰지 않았습니다. 작성자가 확인 필요를 한 번 눌러야 기록이 확정됩니다.
  • 문장이 이동하는 경우까지 시연하지는 못했습니다. 규칙으로만 적었습니다.
