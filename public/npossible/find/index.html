검색어가 기억 안 날 때 — 단어 대신 맥락으로 찾기

“그거 뭐였지”만 남아도 찾아지게. 언제·어디서·누가·무슨 말투였는지를 입력으로 받고, 왜 이 결과인지 함께 보여 줍니다. 이 페이지의 검색은 실제로 동작합니다.

예시 자료 0건에서 찾습니다
이 조각으로 찾고 있어요 — 빼려면 눌러서 끄세요

이 검색이 하는 일

  • 문장에서 조각을 뽑습니다(명사 후보·숫자·기간 표현).
  • 조각마다 제목·본문·태그에 가중치를 두고 점수를 냅니다.
  • ‘언제’는 감쇠로만 씁니다 — 오래된 것도 순위에서 사라지지 않게.
  • 결과마다 왜 이 결과인지와 맞은 조각을 표시합니다.
※ 예시 자료는 제가 만든 30건입니다. 실제 네이트 검색 로그가 아닙니다.

내 검색 기록

(아직 검색 없음)

왜 ‘검색어를 못 만드는 것’이 문제인가

검색은 단어를 정확히 아는 사람에게 잘 맞춰져 있습니다. 그런데 다시 찾고 싶은 것은 대개 단어가 아니라 장면으로 기억납니다 — “겨울에, 지하철에서, 누가 말했는데, 숫자가 3%대였어”. 이때 사용자는 검색창 앞에서 멈춥니다. 검색을 못 하는 게 아니라 질의를 만들지 못하는 것입니다.

기억에 남는 것지금 검색창이 받는 것이 안이 받는 것
“겨울쯤”, “작년 말”날짜 필터를 따로 열어야 함문장 안의 시간 표현을 읽어 기간 후보로 제안
“기사였는지 판 글이었는지”전체 검색 → 결과가 섞임‘어디서’ 한 번으로 좁힘 + 결과 카드에 출처 표시
“3%대 숫자”“3%”로 검색하면 잡음이 많음숫자·단위를 따로 조각으로 뽑아 본문 매칭에 사용
“누가 말했는지”없음기사·사람 글 구분
미션 경계. ‘읽던 뉴스를 다시 찾는’ 기록 자동 저장(다른 미션)이 아니라, 질의를 만들지 못하는 순간의 입력 방식입니다. 방문 기록이 없어도, 다른 기기에서 봤어도 동작해야 하므로 입력 자체를 바꿉니다.

※ 위 관찰은 일반적인 검색 사용 경험에서 출발한 문제 정의이며, 네이트 사용자 로그로 검증한 수치는 아닙니다. 검증 계획은 ④에 적었습니다.

질의 → 조각 → 결과의 흐름

[입력] "겨울에 본 기사인데 전세 대출 금리 3%대"
   ├ 조각 추출   : 전세, 대출, 금리, 3%, 겨울(시간 표현)
   ├ 시간 해석   : "겨울" → 1년 범위 후보(사용자가 끌 수 있음)
   ├ 필드 가중치 : 제목 3.0 · 태그 2.0 · 본문 1.0
   ├ 점수        : 조각별 (정확 일치 1.0 / 부분 일치 0.4) × 필드 가중치 합
   └ 시간 감쇠   : score × (1 + 0.15 × 최근성) — 오래된 문서를 지우지 않음
[결과] 카드마다 맞은 조각을 하이라이트 + "왜 이 결과인지" 한 줄
[실패] 조각이 하나도 안 맞으면 → "기억 조각을 바꿔 보세요"와 함께 자주 쓰는 조각 제안

화면 규칙

  • 결과를 숨기지 않습니다. 상위 5개는 항상 보이고, 점수는 막대와 숫자로 함께 표시(왜 1등인지 확인 가능).
  • 조각 칩은 끄고 켤 수 있습니다. 자동 해석이 틀렸을 때 사용자가 바로 고칠 수 있어야 자동화가 실패해도 검색이 망가지지 않습니다.
  • 시간은 감쇠만. “최근 것만” 같은 강한 필터는 사용자가 고를 때만.
  • 출처(뉴스/판/쪽지/검색기록)를 항상 표시 — 같은 사건이라도 출처가 다르면 신뢰가 다릅니다.

엣지케이스

상황처리
조각이 전부 흔한 단어(“그거”, “있잖아”)점수 계산 대신 “무엇을 찾는지 한 조각만 더 알려 주세요”로 되묻고, 최근 항목을 보여 줌
시간 표현이 모호함(“얼마 전”, “한참 전”)기간을 단정하지 않고 후보 2개(“최근 1달 / 최근 1년”)를 칩으로 제안
같은 사건 여러 출처중복 묶음 — 대표 1건 + “비슷한 결과 3건” 접기
개인 기록(쪽지·검색기록)본인 것만 검색. 결과 카드에도 ‘내 기록’ 표시, 공유 링크 생성 불가
오타·띄어쓰기한글 2글자 단위 부분 일치로 흡수(‘전새대출’ → ‘전세대출’과 부분 일치)
결과 0건“없어요”로 끝내지 않고, 맞은 조각 수 · 가장 가까운 1건 · 조각 제안을 보여 줌
느린 회선입력 중 300ms 디바운스 후 1회 요청, 이전 결과 유지(화면 비우지 않음)
키보드·낭독기결과 개수를 aria-live로 알림(“결과 3건”), 카드마다 제목·출처·날짜를 한 문장으로

부작용

  • 자동 해석이 틀리면 더 나빠짐 — 조각 칩을 끌 수 있게 하고, 해석을 화면에 그대로 노출.
  • 개인정보 — 쪽지·검색기록은 본인 범위 안에서만. 서버 로그에 질의 원문을 남길 때는 목적·보관 기간을 명시(가능하면 조각만 저장).
  • 연산 비용 — 조각 추출은 질의당 1회, 캐시 가능. 결과 개인화는 넣지 않음(설명 가능성 우선).

지금 확인되는 것 / 확인해야 할 것

이 페이지에서 실제로 확인 가능한 것. 아래 검색창은 예시 자료 30건에 대해 정말로 동작합니다. 문장을 넣으면 조각이 뽑히고, 점수·근거와 함께 결과가 나옵니다. 다만 자료가 30건이라 ‘검색 품질’의 증거가 아니라 동작·설명 가능성의 증거입니다.

검증 설계

  • 실제 로그 1만 건으로 오프라인 평가: 같은 질의에 대해 키워드 검색 vs 조각 검색의 상위 3개 적중률 비교(정답 라벨은 사람 2명이 붙임).
  • 소규모 사용성 테스트 5명: “지난달에 본 글 다시 찾기” 과제로 성공률·소요 시간 측정.
  • A/B: 현행 검색 / 조각 입력. 주 지표 상위3 클릭률, 보조 재검색률.

아직 확인하지 못한 것

  • 한국어 조각 추출의 실제 품질 — 지금 구현은 규칙 기반(공백·2글자 bigram)이고 형태소 분석기가 아닙니다.
  • 자료 30건은 손으로 만든 예시라 실제 문서 분포(길이·중복·표제어)와 다릅니다.
  • 감쇠 계수 0.15는 근거 있는 값이 아니라 조정 가능한 초기값입니다.
  • 네이트 검색의 실제 랭킹·색인 구조 — 확인하지 못해 ‘대체’가 아니라 ‘입력층’ 제안으로 범위를 좁혔습니다.

받은 반응바꾼 것
사용자 패널 — “예시가 18건이라 실제 글이 많아져도 잘 찾을지는 궁금해요”자료를 30건으로 늘리고, 질문마다 정답 문서를 붙인 라벨 질의 10건을 만들어 페이지 안에서 바로 채점합니다(아래 표). 규모 한계는 ④에 그대로 적었습니다.
리뷰어 — “일반 키워드 검색보다 원하는 문서를 더 잘 찾는지 판단하기 어렵다”같은 질의에 대해 키워드 일치 검색과 조각 검색을 나란히 돌려 hit@1·hit@3을 비교합니다. 조사·어미가 붙은 문장형 질의에서 차이가 나는 지점을 표로 확인할 수 있습니다.
운영 감사 — “대규모에서의 응답 속도·품질 모니터링 비용”조각 추출 규칙을 한 곳(추출 함수)으로 모으고, 추출 실패·0건을 지표로 남기도록 정의했습니다(④). 규모 검증은 아직 못 했다고 명시했습니다.

지금 이 자리에서 잰 결과 (라벨 질의 10건 · 자료 30건)

이 숫자의 한계를 먼저 말합니다. 정답 라벨은 제가 붙였고, 자료는 제가 쓴 30건입니다. 실제 네이트 문서 분포(길이·중복·표제어·광고)와 다르며, 표본이 작아 ‘조각 검색이 더 낫다’는 일반 주장의 근거가 아닙니다. 이 표가 보이는 것은 같은 조건에서 두 방식이 어떻게 갈리는지이고, 규모 검증은 ④의 계획(로그 1만 건 오프라인 평가)으로 남겨 두었습니다.

바꾸지 않은 것

  • 랭킹 모델을 키우지 않았습니다. 설명 가능성(왜 이 결과인지)을 먼저 지키는 것이 이 안의 주장이므로, 학습 기반 재정렬은 넣지 않았습니다.
  • 개인화를 넣지 않았습니다. 같은 질의에 같은 결과가 나와야 검증·디버깅이 됩니다.
  • 결과 개수를 부풀리지 않았습니다. 관련 없는 문서를 채워 넣지 않고, 없으면 없다고 보여 줍니다.
