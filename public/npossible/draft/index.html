쓰던 글, 어디까지 저장됐는지 보이게

저장은 조용히 하되, 돌아온 사람에게는 “살아 있다”를 먼저 보여 줍니다. 이 페이지는 정말로 새로고침해도 글이 남습니다.

판 글쓰기 0자
아직 저장 전
입력을 멈추면 1초 안에, 계속 쓰는 동안에도 2초마다 이 기기에 저장됩니다. 서버로는 아무것도 보내지 않습니다.

지금 상태

저장 기록

같은 글의 이전 저장 지점입니다. 되돌리고 싶을 때 바로 그 자리에서 이어 씁니다.

보관과 삭제

기한이 지난 초안은 열 때 바로 지웁니다. 지운 뒤에는 되돌릴 수 없고, 서버에 사본이 없으므로 복구 요청도 없습니다.

미션이 짚은 것과 화면의 답

미션의 문장화면에서의 답
쓰다가 화면이 닫히거나 새로고침되면 글이 지워진다입력이 멈추면 1초 안에 이 기기에 저장합니다. 화면을 닫아도 남습니다. 위 화면 닫기(새로고침)을 눌러 직접 확인할 수 있습니다.
저장은 쓰는 동안 조용히 일어나야 한다저장할 때 팝업이나 창을 띄우지 않습니다. 상태 줄의 점과 문장만 바뀝니다.
돌아온 이용자에게는 글이 살아 있다는 걸 먼저 보여 줘야 한다돌아오면 편집 화면 위에 “쓰던 글이 있어요”가 먼저 뜨고, 마지막 저장 시각·글자 수·마지막 문장이 함께 보입니다.
언제, 어디까지 저장됐는지가 보여야 믿을 수 있다상태 줄에 시각과 글자 수를 쓰고, 저장된 부분과 아직 안 된 부분을 막대로 나눕니다. 초안을 불러오면 마지막 저장 지점을 문장으로 표시합니다.
복구는 한두 번 동작 안에 있어야 한다돌아오면 이어 쓰기 한 번으로 원래 화면이 됩니다. 다른 선택은 “새로 쓰기” 하나뿐입니다.
보관 기한과 사생활1일·7일·30일 중 고르고, 지난 초안은 열 때 지웁니다. 저장 위치는 이 브라우저 안이며 서버 전송이 없습니다.

왜 ‘저장했습니다’ 알림을 띄우지 않는가

쓸 때마다 알림이 뜨면 글이 방해받고, 사람은 곧 알림을 닫아 버립니다. 대신 상태 줄에 같은 정보를 계속 두고, 돌아왔을 때만 큰 안내를 띄웁니다. 알림은 필요할 때 한 번, 나머지는 조용히.

한계. 이 프로토타입은 이 브라우저의 저장소에만 씁니다. 다른 기기에서 이어 쓰기, 서버 장애 복구, 브라우저 저장소를 지운 경우는 다루지 않습니다. 그 셋은 아직 확인하지 못했습니다.

저장 규칙

[입력] → 1초 동안 입력 없음 → 저장
       제목이나 본문이 비어 있으면 저장하지 않음
[저장] 시각, 제목, 본문, 마지막 30자, 기한을 함께 기록
       기록은 20초 이상 차이날 때만 남김 (최근 3개 유지)
[열기] 초안 있음 → 배너 먼저 ("쓰던 글이 있어요")
       ├─ 이어 쓰기 → 편집 화면 + 마지막 저장 지점 표시
       ├─ 새로 쓰기 → 빈 화면 (초안은 기록에 남김)
       └─ 기한 지남 → 지우고 "보관 기한이 지나 지웠어요" 한 줄
[삭제] 이용자가 직접 지우면 즉시 삭제, 되돌리기 없음

저장 상태 문장

상태화면 문장
입력 중, 아직 저장 전“저장 중…” (노란 점)
저장됨“저장됨 · 12:04:33 · 본문 412자” (초록 점)
저장 실패“저장하지 못했어요. 이 화면을 닫으면 글이 사라집니다.” (빨간 문장, 닫기 전 확인)
기한 지난 초안“보관 기한이 지나 지웠어요.” (삭제 시각 표시)

엣지케이스

상황처리
제목만 쓰고 본문은 비어 있음초안으로 저장합니다. 복구 문구는 “제목만 저장됐어요 · 본문은 아직 없습니다”.
같은 글을 두 탭에서 엶나중에 저장한 쪽이 남고, 다른 탭에는 “다른 창에서 이어 썼어요” 한 줄과 [불러오기]를 띄웁니다(이 프로토타입에서는 문구만 있고 동작은 확인하지 못했습니다).
저장 공간이 부족함저장 실패 문장을 띄우고, 오래된 기록부터 지우겠다고 알린 뒤 한 번 더 시도합니다.
이용자가 초안을 지움즉시 지우고 “지웠어요. 되돌릴 수 없어요”를 보여 줍니다. 서버 사본이 없으므로 복구 요청을 받지 않습니다.
화면 낭독기저장 문장은 조용히 바뀌므로 aria-live=polite로 읽되, 30초에 한 번만 읽습니다(반복 낭독 방지).

이 페이지에서 실제로 잰 값

배포 뒤에 재야 할 것

  • 복구 성공률: 초안이 있던 사람 중 실제로 이어 쓴 비율.
  • 복구까지 걸린 동작 수: 배너 → 이어 쓰기까지 누른 횟수(이 화면은 1회).
  • 저장 실패율과 실패 뒤 이탈률.
  • 초안 보관 기한을 실제로 얼마나 쓰는지. 7일은 제가 정한 값이고 근거 자료가 없습니다.

아직 모르는 것

  • 사람이 이 화면을 실제로 써 본 결과가 아닙니다. 제가 새로고침해 확인한 것까지입니다.
  • 모바일 브라우저가 백그라운드에서 저장소를 지우는 비율은 모릅니다.
  • 서버 저장과 비교한 비용은 다루지 않았습니다. 이 안은 서버를 쓰지 않습니다.

직접 해 보는 순서

확인하려는 것하는 방법
정말 저장되는가① 체험에서 글을 조금 쓰고 1초 기다립니다. 상태 줄이 “저장됨 · 시각 · 글자 수”로 바뀝니다.
새로고침해도 남는가화면 닫기(새로고침)을 누릅니다. 페이지가 실제로 다시 열리고, 맨 위에 초록/파란 배너 “쓰던 글이 있어요”가 뜹니다.
복구가 한 번에 되는가이어 쓰기를 누릅니다. 제목·본문이 그대로 돌아오고 마지막 저장 문장이 표시됩니다.
언제 저장됐는지 보이는가상태 줄의 시각과 글자 수, 그리고 오른쪽 저장 기록의 목록을 봅니다.
보관 기한이 지키는가기한을 1일로 바꾸고, 브라우저 저장소를 훑어보지 않고도 “지금 지우기”로 즉시 삭제되는 것을 확인합니다.

※ 사람을 모아 검증한 결과가 아닙니다. 새로고침과 복구는 이 브라우저에서 실제로 일어납니다.

처음 낸 화면에서 받은 반응과 고친 것

받은 반응바꾼 것
파워유저와 리뷰어 “입력을 1초 쉬어야 저장되니 계속 쓰다 창이 닫히면 마지막 부분이 날아갈 수 있고, 1초마다 저장과 1초 멈춘 뒤 저장은 다르다”입력이 이어지는 동안에도 2초마다 저장하고, 화면이 닫히거나 가려지는 순간 한 번 더 저장합니다. 상태 줄에 저장 이유를 함께 적습니다. [아래 시험 버튼]
일반 사용자 “다른 기기에서는 초안을 못 불러오는 점이 아쉽다”이번 버전에는 넣지 못했습니다. 서버 저장이 필요하고, 그 경우 사생활 설명과 보관 기한을 다시 설계해야 합니다. 대신 무엇을 저장하고 얼마나 두는지를 아래에 적었습니다. 한 기기 안에서만 되는 한계는 그대로 밝힙니다.
운영감사 “저장 공간이 부족하거나 브라우저 데이터가 삭제되면 복구할 수 없으니 실패와 한계를 명확히 안내해야”저장 실패 문장을 따로 두고, 복구할 수 없는 세 경우를 화면에 적었습니다. [아래 시험 버튼]

입력 직후 닫기 시험

글자를 더한 뒤 기다리지 않고 바로 새로고침합니다. 돌아온 뒤 저장된 글자와 쓴 글자를 비교해 유실량을 보여 줍니다.

다른 기기에서 이어 쓰기 (아직 없음)

항목내용
필요한 것계정 로그인과 서버 저장. 이 화면은 서버가 없어서 같은 기기 안에서만 됩니다.
저장하면 생기는 문제글 내용이 서버에 남습니다. 지금은 기기 밖으로 나가지 않습니다. 서버로 옮기면 보관 기한과 삭제 요청, 유출 시 책임을 다시 정해야 합니다.
이번에 한 것같은 브라우저의 다른 탭에서 고친 경우는 저장 값이 바뀌면 알림 줄을 띄우도록 했습니다. 다만 탭 사이 동작은 직접 확인하지 못했습니다.

복구할 수 없는 경우

  • 브라우저 저장 공간이 가득 찼을 때. 저장 실패 문장을 띄우고 화면을 닫지 말라고 알립니다.
  • 브라우저 데이터를 지웠을 때. 사본이 없어 복구할 수 없습니다.
  • 시크릿 창이나 기기를 바꿨을 때. 그 창을 닫으면 사라집니다.
