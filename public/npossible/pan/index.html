미션 자료 4개를 그대로 화면 설계로 옮겼습니다

자료는 “설정이 없다”가 아니라 “쓸 때·고칠 때 그 자리에 없다”는 걸 보여 줍니다. 그래서 새 설정 화면을 만드는 대신, 이미 있는 흐름의 문장과 자리를 바꿉니다.

자료자료가 말하는 것이 안에서의 대응
기록 1 — 다 쓰고 범위는 한 번도 안 열고 게시범위를 고르는 ‘행동’이 아예 일어나지 않음고르지 않아도 게시 버튼 문구가 ‘이웃 12명에게 게시’. 행동을 요구하지 않고 결과를 먼저 말함
기록 2 — 게시 후 글 아래 표시를 보고 되물음게시 뒤에야 누구에게 갔는지 알게 됨게시 결과 화면에 고른 값 ↔ 실제 적용 값 대조와 ‘지금 바꾸기’를 함께 둠
기록 3 — 수정 화면에서 설정 못 찾고 나옴고칠 때 같은 자리에 없음수정 화면 상단에도 같은 띠(지금 이웃 12명에게 공개 중 · 바꾸기)를 고정
기록 4 — 두 번째 글은 설정 화면부터 열어 봄한 번 겪으면 배우지만 비용이 큼처음 고른 값을 다음 글에도 같은 자리에 두고, 띠가 ‘지난번과 같아요’라고 알려 줌
모의 반응 — “글은 다 썼는데 누가 볼 수 있는지는 모르겠어요”모르는 채로 게시하게 됨띠의 두 문장(누가 / 검색 노출)을 접지 않고 항상 노출. 선택지마다 실제 인원·검색 여부를 붙임
이미 나온 안과 다른 점. 게시 직전 ‘확인 창’은 이미 시도된 방식입니다(사용자 반응: “갑자기 박스가 뜨니까 당황했어요”, “한 번뿐이라 놓치면 끝이에요”). 이 안은 단계를 하나도 늘리지 않습니다. 확인을 새 화면이 아니라 이미 누르는 버튼의 글자로 옮깁니다. 확인을 강요하지 않아도 매번 읽히는 자리이기 때문에, 눌러 버릇해 무시되는 문제도 생기지 않습니다.

화면 상태 전이

[글쓰기]
  ├─ 범위 미선택(첫 글)      → 버튼 = "이웃 12명에게 게시"(기본값 이름을 그대로 씀)
  ├─ 범위 선택 = 이웃        → 띠 초록,  버튼 "이웃 12명에게 게시"
  ├─ 범위 선택 = 전체        → 띠 주황,  버튼 "전체 공개로 게시"  + 문장 "검색에도 잡혀요"
  └─ 범위 선택 = 나만        → 띠 회색,  버튼 "나만 보기로 저장"
[게시]  → 서버 적용값 재조회(publish 응답의 effective_scope)
        ├─ 일치 → "이웃 12명에게 공개했어요" + [지금 바꾸기]
        └─ 불일치 → 게시 중단, "저장된 설정과 달라요. 다시 확인할게요" + 선택 시트 자동 열기
[수정]  → 상단 띠에 현재 공개 상태 + [바꾸기] (기록 3 대응)
[뒤로]  → 로컬 초안 저장(본문+제목+범위), 복귀 시 "작성 중인 글을 이어 씁니다"

문구 규칙 (한 곳에서 관리)

범위 이름·설명·인원·검색 노출 여부는 화면에 손으로 적지 않고 scope_policy 값에서 만듭니다. 정책이 바뀌면 띠·버튼·미리보기가 동시에 바뀌므로, 표시와 실제 권한이 어긋날 자리가 줄어듭니다.

scope_policy = {
  neighbor: { label:"이웃 공개",  short:"이웃 {n}명",        searchable:false,
              why:"이웃을 맺은 사람만 볼 수 있어요. 검색에는 안 나와요." },
  public:   { label:"전체 공개",  short:"전체 공개",         searchable:true,
              why:"판 방문자 누구나 볼 수 있고 검색에도 잡혀요." },
  private:  { label:"나만 보기",  short:"나만",              searchable:false,
              why:"저장만 하고 아무에게도 보여 주지 않아요." }
}
// 버튼 라벨 = short + "에게 게시"  → 정책 수정이 곧 라벨 수정

엣지케이스

상황처리
이웃이 0명‘이웃 공개’ 카드에 “이웃이 아직 없어서 나만 볼 수 있어요”를 쓰고, 버튼은 “나만 보기로 저장”. 0명에게 게시하는 허수를 만들지 않음
쓰는 중 이웃이 줄어듦(12 → 9)띠의 인원을 게시 시점에 다시 계산. 게시 결과에 “지금 이웃 9명에게 공개됐어요”로 확정값 표시
전체 공개 + 민감 표현게시 전 비속어·개인정보(전화번호·주소 패턴) 검사. 걸리면 범위를 낮추도록 제안하고, 그 사실을 버튼 옆에 한 줄로 표시
다른 기기에서 범위를 바꿈게시 요청에 scope_rev를 실어 보내고, 서버 값이 다르면 게시 중단 후 재확인
오프라인·느린 회선버튼은 로컬 정책값으로 즉시 그려지고(문구 지연 없음), 게시 결과만 서버 응답을 기다림. 실패 시 초안 유지
키보드만 사용띠 → 바꾸기 → 라디오 3개 → 게시 순서로 Tab 이동. 라디오는 화살표 키로 이동, 선택 즉시 띠·버튼 라벨 갱신
화면 낭독기범위 변경 시 aria-live=polite로 “공개 범위가 이웃 12명에게 공개로 바뀌었습니다. 게시 버튼: 이웃 12명에게 게시”를 읽음
색 구분이 어려움초록/주황을 색만으로 쓰지 않고 문장(검색에도 잡혀요)과 버튼 라벨로 구분. 대비 4.5:1 이상
이미 게시한 글 수정수정 화면에서도 같은 띠. 저장 시 “이웃 12명 → 전체 공개”처럼 바뀐 방향을 한 줄로 확인

부작용과 완화

  • 안내 피로 — 띠를 크게 만들지 않고 12px 두 줄로 고정. 반복 사용자는 문장을 읽지 않아도 버튼 라벨에서 답을 얻음.
  • 인원 표시의 정확성 — ‘이웃 12명’은 캐시가 아니라 게시 시점 계산값. 캐시를 쓰면 5분 지연을 명시(“약 12명”)하고, 게시 결과에서 확정값을 다시 보여 줌.
  • 프라이버시 — 이웃 수는 내 화면에만 보이고 상대에게 노출하지 않음. 다른 사람 글에는 인원을 표시하지 않음.
  • 게시 완료율 하락 — 추가 단계가 없으므로 하락 요인은 문구 길이뿐. A/B로 게시 완료율을 가드레일 지표로 감시(아래 ④).

무엇을 재고, 무엇을 아직 모르는가

이 출품에는 아직 실사용자 검증 결과가 없습니다. 대신 (1) 이 페이지에서 실제로 남는 행동 기록, (2) 배포 직후 바로 돌릴 수 있는 측정 설계, (3) 지금 확인할 수 없는 것을 구분해 적었습니다.

1) 지금 이 페이지에서 실제로 확인되는 것

  • 범위를 열지 않고 게시할 때 버튼에 인원이 적혀 있는지 — 체험 탭의 내 확인 순서에 그대로 남습니다.
  • 전체 공개를 골랐을 때 버튼 라벨과 띠 문장이 함께 바뀌는지 — 잘못된 상태가 하나만 바뀌는 경우가 없도록 한 상태에서 파생되게 구현했습니다.
  • 뒤로 가기 후 초안·범위가 남는지 — 보고 있던 화면에서 바로 확인 가능.

※ 심사자가 이 페이지에서 누른 순서는 서버로 전송하지 않습니다. 브라우저 안에서만 보입니다.

3) A/B 설계

  • A 현행(설정 숨김) / B 버튼 라벨 + 상단 띠 / C B + 게시 직전 확인창(이미 나온 안)
  • 단위: 사용자 단위 무작위 배정(첫 글 작성자만), 기간 2주, 표본은 첫 글 작성자 기준 주 1,000명 이상일 때 1주차 중간 분석 없이 종료.
  • 주 지표: 첫 글 무범위 게시율. 보조: 게시 후 범위 변경률. 가드레일: 게시 완료율, 작성 소요 시간.
  • C가 B보다 나으면 확인창을 되살리는 게 아니라, B의 문장을 더 구체화하는 쪽으로 해석합니다(단계 추가는 비용이 크고, 무시 습관이 생김).

4) 아직 확인하지 못한 것

  • 초보자가 ‘이웃 12명’이라는 문구에서 실제로 범위를 이해하는지 — 인지 인터뷰 필요(5명, 15분). 이 출품에는 없다.
  • 버튼 라벨이 길어졌을 때 모바일에서 잘리지 않는지 — 실제 판 UI 폭·폰트에서 재확인 필요.
  • ‘확인 피로’가 실제로 줄어드는지 — B/C 비교 결과 없이는 단정하지 않음.
  • 이웃 수 계산의 서버 비용 — 이웃 목록이 큰 계정(수천 명)에서의 응답 시간 미측정.
주장하지 않는 것. “공개 사고가 줄어든다”는 결과는 아직 없습니다. 이 출품이 보이는 것은 설계와 재현 가능한 프로토타입, 그리고 측정 계획까지입니다.

데모 A — 게시 시점 재계산

쓰는 동안 이웃이 줄면, 화면의 ‘12명’은 사실이 아니게 됩니다. 그래서 게시할 때 서버가 다시 셉니다.

쓰는 중: 이웃 12명에게 공개

데모 B — 다른 기기에서 범위가 바뀐 경우

화면에 보이는 값과 저장된 권한이 다르면 게시하지 않습니다. 보여 주는 값과 실제 값이 어긋난 채 올라가는 것이 가장 위험합니다.

3문항 이해 확인 (라벨만 보고 답할 수 있나)

버튼과 띠만 보고 답해 보세요. 정답은 화면에 이미 적혀 있습니다.

1. 이 글은 누가 볼 수 있나요?
2. 이 상태에서 이 글은 검색에 잡히나요?
3. 전체 공개를 고르면 게시 버튼은 어떻게 바뀌나요?

※ 이건 심사자가 자기 화면에서 푸는 확인입니다. 일반 사용자 검증 결과가 아니며, 그렇게 주장하지 않습니다.

바꾸지 않은 것 (의도)

  • 확인 창을 다시 넣지 않았습니다. 사용자 패널이 “확인 자체는 좋다”고 했지만, v1에서 단계를 늘리지 않는 것이 이 안의 핵심이라 유지했습니다. 대신 확인이 필요한 순간(전체 공개·불일치)에만 멈춥니다.
  • ‘스팸 같은 문구’를 넣지 않았습니다. 판에는 없던 판정을 새로 만들면 오탐의 책임이 사용자에게 남습니다.
  • 결과 점수를 인위적으로 올리지 않았습니다. 검증 결과가 없는 주장은 빼고, 확인 가능한 조작 수·상태 전이만 남겼습니다.
